# 开销实测（2026-09-22）


默认每秒线程扫描在本次测试中消耗约 **单核 3.85%**，进程扫描约 **3.18%**；默认模式进程峰值 RSS 不超过 **20.69 MiB**。保留 1 秒作为默认间隔；200 ms 模式的扫描开销明显更高。极低优先级降低调度竞争，并不会免除扫描成本。

以下为同一匿名 Linux 环境的开销测试。线程模式最多扫描约 3,150–3,222 个线程，进程模式检查 2,548 个主线程；监视 160 个逻辑核，阈值为单核 1%，默认过滤运行用户。未制造额外压力，其他工作负载未隔离；普通模式没有额外绑核，低优先级模式使用脚本自身的空闲核选择。

每组连续运行 15 秒，重复 3 次，轮换组间顺序。CPU 用量按 `100 × (user + system) / wall` 计算，100% 表示占满一个逻辑核，包含启动、退出及已回收子进程的 CPU 成本。标准输出重定向到 `/dev/null`，仍包含提示格式化成本，但不包含终端渲染成本。峰值 RSS 为 `wait4` 返回的最大驻留集，不包含文件描述符等内核内存，也不是并发进程内存之和；测量驱动自身开销不计入。

| 模式 | 单核 CPU 中位数 | 3 次 CPU 范围 | 每轮扫描均值的中位数 | 3 次最大峰值 RSS | 每次采样数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 线程扫描，1 秒 | 3.85% | 3.82%–3.87% | 36.32 ms | 20.69 MiB | 15 |
| 进程扫描，1 秒 | 3.18% | 3.08%–3.19% | 29.62 ms | 20.31 MiB | 15 |
| 线程扫描，1 秒，极低优先级 | 3.80% | 3.75%–3.86% | 34.90 ms | 20.75 MiB | 15 |
| 线程扫描，200 ms | 16.74% | 16.38%–16.84% | 33.12 ms | 20.88 MiB | 75 |

全部 12 次运行均使用 `schedstat-ns`，没有计时降级、扫描超时或权限拒绝计数警告；普通账户的可见范围提示仍然适用。进程模式只少扫描约 600 个工作线程，因此收益有限；不应为了这个收益忽略其漏检工作线程的限制。普通模式与低优先级模式的细小 CPU 差异不能视为稳定的性能提升。

这些数据只描述本次线程规模和负载条件，不能保证其他机器、更多线程或大量输出时的开销，也不等同于对被测业务的性能影响。

复现命令（在 Linux 上运行）：

```bash
python3 scripts/measure_overhead.py --cpus 0-159 --duration 15 --repeats 3 > overhead.jsonl
```
